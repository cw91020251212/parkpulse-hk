# ParkPulse HK PWA 電單車支援範圍審核

**審核日期：2026-10-09**
**範圍：**「有位」、「開放」、「車高」、「EV」、「無障礙」及附近設施在電單車模式的語義與缺口。此紀錄只研究程式及官方公開資料，沒有修改產品程式或既有文件。

## 判斷摘要

「有位」是此範圍內唯一明確按所選車種取值的篩選：切換至電單車後，狀態從 `motorCycle` 空位記錄計算；但沒有官方電單車記錄時，預設「只看有位」會排除該車場。「開放」按車場整體的 `opening_status` 判斷，並非電單車車位層級。車高、EV、無障礙與附近設施沒有一致的電單車專屬語義：車高是整個車場高度限制，EV 是車場/充電器存在標記，無障礙是跨車種合併的設施判斷；附近設施則是按中心及距離列出，與目前車種無關。尤其 EV 與無障礙篩選可能讓使用者誤以為符合電單車特定條件，現有官方欄位不足以作此保證。

## 逐項審核

### 1. 有位

**現況。** `App.tsx` 依目前 `vehicleType` 從空位記錄選取對應欄位，再交由 `getVacancyStatus` 判斷。電單車模式會讀 `motorCycle`。`isAvailable` 只接受 `count` 或 `available`；而 `getVacancyStatus` 對 `A` 類型把正數標為空位數、零標為已滿，對 `B` 類型只有值為 1 才視為有位。初始篩選 `availableOnly: true`，所以缺記錄或 `-1` 的未知狀態在預設狀態下不會顯示。

**電單車影響。** 語義基本正確：是電單車泊位空位，而非私家車空位。須注意政府 API 的車種參數列明 `motorCycle`，但逐個停車場可能沒有此車種記錄；空記錄不等同「沒有電單車泊位」，應表述為「官方空位資料未提供」而不是有位/已滿。API 現時回應可見電單車記錄包含正數、零及 `-1` 等值，證明未知與已滿需區別。[1] [2]

**最小修正。** 保留車種關聯；在篩選器說明或結果狀態上明確區分「沒有電單車空位資料」與「已滿」。評估預設「只看有位」造成無資料車場被隱藏的可發現性問題；不要把缺記錄解讀成無位。

### 2. 開放

**現況。** `openOnly` 檢查 `park.info.opening_status === 'OPEN'`，並排除空位狀態 `closed`。這是停車場層級開放狀態，與 `vehicleType` 無關。繁中提示解釋為「只看官方資料標示開放的停車場，不代表有空位」。官方 API 將基本資料與空位資料分開，基本資料包含開放時間等，空位資料則是空位資訊。[1]

**電單車影響。** 文案已避免把開放誤作有位；但 `OPEN` 不能證明場內電單車時租位此刻開放或可供該使用者使用，也不能取代電單車時段、樓層、預約或營辦商條件。官方電單車 API 樣本中，基本資料回傳 `opening_status` 及備註文字，備註可載有車種/時段限制，但這是自由文字而非篩選使用的電單車開放旗標。[2]

**最小修正。** 保留為車場整體開放篩選；在電單車模式將名稱/說明明確限定為「車場官方開放狀態」，並提醒車種時段或使用條件需查看車場備註。不可把它改述為「電單車位開放」。

### 3. 車高

**現況。** 控制項在所有車種都出現，提供不限、≥1.8、≥2.0、≥2.2 米。`getHeightLimit` 取 `heightLimits` 中大於零的最低高度；`App.tsx` 以此同一車場高度篩選所有車種。沒有數據或全為零即視為未提供，不符合任何已選最低高度。官方 API 說明基本資料可能提供高度限制。[1]

**電單車影響。** 欄位描述的是車場通行高度限制，不是電單車車身高度或電單車泊位的專屬限制。電單車可能不需受私家車入口限高同樣約束，但公開欄位沒有說明該高度是否適用全部車種，也沒有提供電單車專屬高度限制；故不能確認此篩選對電單車是否有實際價值。取最低數值亦可能把多個入口/分區高度簡化為一值。

**最小修正。** 未取得欄位定義或營辦商明確文案前，不應宣稱為電單車限高。可在電單車模式隱藏/停用此篩選，或標示「車場公布高度限制（未按車種區分）」；保持未知值不被視為符合。

### 4. EV／充電設施

**現況。** `hasEvFacility` 在車場 `facilities` 含 `evCharger` 或找到距車場座標/名稱/地址符合門檻的環保署充電器時返回真。篩選本身不讀 `vehicleType`。車位空位記錄另有 `vacancyEV`，但此篩選沒有使用它。官方環保署說明公共充電網絡主要作補充用途，並提供公共充電樁位置資料；其網頁亦明確涵蓋電動電單車作為電動車型號範疇，但沒有在該處承諾任何個別充電點適用所有車種。[3]

**電單車影響。** 目前語義只是「車場/附近匹配到 EV 充電設施」，不代表電動電單車可接駁、接口相容、可停在該樁旁充電、該設施對公眾開放或即時可用。位置匹配本身亦是程式啟發式。將它用作「電動電單車可充電」的保證會超出欄位證據。

**最小修正。** 將文案界定為「有 EV 充電設施資料」，電單車模式提供醒目限制：不核實電動電單車相容性/可用性；跳轉或查閱充電點營運商資訊。若未能取得按充電器提供的車種/接口/使用限制官方欄位，避免標示為電單車充電支援。

### 5. 無障礙

**現況。** `hasAccessibleParking` 若車場設施含 `disabilities`，或任一車種的 `spaceDIS > 0` 即為真。篩選未按目前車種選取；空位回應雖可能有 `vacancyDIS`，本篩選不使用實時無障礙空位數。當「只看無障礙」沒有結果時，最近車場搜尋也同樣以此跨車種函式判斷。

**電單車影響。** 因為任一車種的無障礙位即可令車場入選，它不代表有電單車無障礙泊位、無障礙電單車泊位正在空置，亦不代表設施符合個別使用者需要。欄位是 `spaceDIS`，但程式把它當有無指標並跨車種合併；沒有公開欄位證據顯示電單車 `spaceDIS` 的含義、適用資格或實際設施範圍。[2]

**最小修正。** 不可把該篩選命名或描述成「無障礙電單車位」。優先以目前車種的 `spaceDIS`/`vacancyDIS` 判斷（前提是官方字典確認該欄的車種語義）；若語義未明，電單車模式停用篩選或改為「車場有無障礙相關資料」，並清楚標示非車種專屬且非即時可用性。

### 6. 附近設施

**現況。** 洗手間、油站、ATM、路邊位是 `facilityMode` 顯示模式，不是停車場條件篩選；啟用後地圖及結果清單改顯示附近設施，停車場結果不再顯示。前 3 類按中心 2 公里及資料類別列出。路邊位另以 `availableOnly` 透過 `limitOnStreetResults` 篩選空置狀態。上述四類均沒有以 `vehicleType` 作篩選。運輸署另有獨立的「路邊電單車泊車位分佈」資訊頁，表示電單車路邊泊位是另一資料範疇。[4]

**電單車影響。** 洗手間、油站、ATM 是一般附近地點，與車種無關，現有語義合理。路邊位模式的來源和文案稱運輸署智能咪錶及路旁感應試行位；程式記錄類型有 `vehicleType?`，但此處沒有按電單車篩選。故不能將該模式結果視作電單車路邊泊位，也不能由運輸署的獨立電單車泊位分佈頁推定兩者資料涵蓋一致。切換附近模式時仍顯示全域篩選控制，可能使使用者誤以為「有位」等停車場篩選套用於附近設施；實際上只有路邊狀態限位會用 `availableOnly`。

**最小修正。** 保持一般附近設施不受車種影響；分開標示「停車場篩選」與「附近設施」。路邊位只有在官方來源欄位確認車種且涵蓋電單車後，才提供電單車限定結果；否則明示目前是咪錶/感應試行資料，不代表電單車專用泊位。

## 公開資料不能確認的限制

1. 官方一站式 API 文件列出 `motorCycle` 為可查詢車種，並說明 `info`、`vacancy` 的用途，但本次可讀到的頁面沒有呈現完整資料字典。無法由已核實公開文本確認 `spaceDIS`、`vacancyDIS`、`heightLimits` 在各車種中的正式定義及 `facilities` 代碼的語義。[1]
2. 無法確認各停車場空位資料是否涵蓋所有電單車泊位、更新頻率一致性、`-1` 的正式定義，或沒有 `motorCycle` 記錄代表何種狀況。產品只可安全地把缺記錄視作未知。
3. 無法由環保署公共充電樁位置資料的概述確認個別充電器是否支援電動電單車、接口相容、車位准入、收費/使用限制或即時狀態。不得把「充電器附近」等同「可供電單車充電」。[3]
4. 無法確認 `opening_status` 及車高資料是否有全車種共同適用的正式定義；公開資料未提供一致的電單車分層/入口限高欄位。
5. 運輸署路邊電單車泊位分佈頁僅指向「香港出行易」查詢，沒有在可讀頁面提供可機器讀取欄位、狀態、空位或完整覆蓋說明。[4]
6. 以上是程式與公開欄位/明確官方文案的靜態審核，不代表對營辦商現場安排、特定停車場或充電樁作實地核實。
