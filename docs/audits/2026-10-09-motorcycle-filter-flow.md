# ParkPulse HK PWA 電單車篩選流程審核

審核日期：2026-10-09

## 現況（程式碼）

- 車種選取已包含「電單車」：`VEHICLE_TYPES` 有 `motorCycle`，繁中與英文標籤分別是「電單車」及「Motorcycle」（`src/types.ts:1-9`、`src/i18n.ts:398-404`）。選車會更新 `vehicleType` 並清除選取中的停車場卡片，但不清除既有篩選值（`src/App.tsx:154`）。車種和篩選會一併存入瀏覽器偏好（`src/App.tsx:59-65,102`）。
- 附近結果先依所選車種讀取空位，再以附近中心 2 公里內停車場為底，套用只看有位、只看開放、充電設施、無障礙及車高門檻（`src/App.tsx:108-119`）。因此，換成電單車時 availability 資料來源會改用 `motorCycle`，但其他條件不會自動消失。
- 篩選列對所有車種都顯示相同控制：車高、只看有位、路邊位、只看開放、充電設施、無障礙、洗手間、油站、ATM（`src/components/Filters.tsx:21-36`）。後四種附近設施模式和停車場結果互斥；路邊位開關會切換模式而非套用一般停車場篩選（`src/App.tsx:148,131-137`）。
- 空結果文案只在 `hasAccessible` 為真時顯示「無官方無障礙停車場紀錄」及最近無障礙停車場捷徑，否則顯示一般無結果及「取消部分篩選」提示（`src/App.tsx:159`；`i18n.ts:107-111`）。捷徑只會關閉 `availableOnly`、`openOnly`，沒有關閉 `hasAccessible`，且把中心移到最近場地（`src/App.tsx:149`）。
- 卡片的空位及空位數按所選車種取值；總車位和價格也按所選車種讀取。卡片仍一律展示共同車高限制、最多兩種付款方式、充電摘要和無障礙標記；電單車價格可使用相應車種的營辦商價目或結構化／備註價目（`src/components/ParkCard.tsx:15-41`；`src/domain/carpark.ts:27-29,91-103,189-207`）。導航連結以停車場座標開 Google Maps 路線。

## 電單車影響與條件判斷

- **保留「只看有位」及「只看開放」**：兩者是結果狀態／場地營運條件，不是私家車專屬概念。空位入口本身支援按 `motorCycle` 查詢（官方 API 規格列明 `motorCycle` 是有效 `vehicleTypes` 值；[1]）。「只看開放」採用場地開放狀態，而非車種專屬資料（`App.tsx:119`）。
- **「車高」應隱藏或改為車種適用的限制，而非直接沿用現有 ≥ 1.8/2.0/2.2m 篩選**：現有篩選將全場最小高度限值當作單一數字，與選定電單車高度比較（`getHeightLimit`、`App.tsx:119`），UI 仍稱車高（`Filters.tsx:28`）。公開 API 說明只確認基本場地資料含高度限制，未說明此限制是否對電單車適用，也未說明多種車位／入口的高度語義。因此不得將現有高度值推斷為電單車准入限制。最小安全行為是電單車模式隱藏此門檻；若資料字典或場方資料能確證適用，才可按車種恢復。
- **充電篩選應對電單車隱藏，或明確標成「電動車充電」並確認車種支援後才篩選**：目前任何 `motorCycle` 均可被「充電設施」篩出，但匹配依停車場共用設施／附近 EPD 充電器資料，而非電單車可用資格（`App.tsx:119`、`ParkCard.tsx:8-13`）。本次官方公開資料沒有確認所列充電器可供電單車使用；不宜將「有充電設施」呈現為電單車可充電。
- **無障礙條件不應以電單車作為場地可停的證據**：現有 `hasAccessibleParking` 若場地設施標記 `disabilities` 或任何車種有 `spaceDIS` 即回傳真（`domain/carpark.ts:95-97`），篩選不要求 `spaceDIS` 屬於目前所選車種。電單車選取後仍出現無障礙篩選，可能把只有其他車種無障礙泊位的場地納入。建議隱藏電單車模式的此篩選，或使用當前車種的無障礙泊位欄位且只在官方語義足夠明確時保留。公開資料不足以證明電單車有可對應的「無障礙車位」分類。
- **路邊位控制應改成電單車專用路邊泊位入口，不應沿用現有智能咪錶／感應試行狀態清單**：目前 `onStreet` 模式取用通用路邊咪錶／感應試行資料，結果以 `filters.availableOnly` 過濾（`App.tsx:113-115`），而不是依 `vehicleType`（`Filters.tsx:32`）。運輸署把「路邊電單車泊位」另列專頁，指示透過 HKeMobility 查詢；這與本站所述智能咪錶／路旁感應試行位是不同的資料入口。[2] 因此選電單車時應隱藏現有「路邊位」或將它改接運輸署可驗證的電單車泊位資料；不能宣稱目前結果是電單車專用或有即時空位。
- **洗手間、油站、ATM 可保留為周邊設施模式**，但它們是位置周邊搜尋，不是停車場支援條件；切換後應維持清晰的設施結果標籤。現有行為正是清空停車場結果並顯示設施清單（`App.tsx:131-137,159`），無須因電單車改成篩停車場。

## 空白結果與卡片／控制行為的最小修正

1. 車種變更時，按車種重設不適用條件：電單車至少清除 `minHeight`、`hasEv`、`hasAccessible`；如電單車路邊資料尚未接通，亦退出 `onStreet` 模式。避免已保存的私家車篩選讓電單車結果默默變成零筆。
2. 電單車模式隱藏不受證據支持的車高、充電、無障礙控制；只保留有位／開放及獨立附近設施控制。補足控制說明，指出有位狀態來自所選車種的官方停車場資料，仍須以現場為準。
3. 空結果不應只因 `hasAccessible` 狀態而顯示「無官方無障礙紀錄」。清除不適用篩選後，顯示符合車種的零結果及可逐項放寬的條件；對電單車不要顯示「最近無障礙停車場」捷徑。捷徑目前也未清除 `hasAccessible`，應一併修正其篩選重設邏輯。
4. 電單車卡片只把有來源依據的 `motorCycle` 空位、車位數及車種收費當作電單車資料。車高需在適用性未確認前避免顯示為電單車准入限制；充電／無障礙標籤不可暗示電單車可用。保留距離、場地名稱、狀態更新時間及座標導航。
5. 若新增電單車路邊結果，需用專屬來源標記及相符空位／狀態語義；在取得可機器讀取且可確認的官方資料前，不把 HKeMobility 的查詢指引轉譯成未驗證的站內即時結果。

## 官方證據及未確認限制

官方一站式停車場 API 說明：`info` 回傳基本停車場資料（位置、收費、開放時間、高度限制），`vacancy` 回傳空位資料；`vehicleTypes` 明列 `motorCycle`。這支持按電單車取得停車場資料，但不保證每個停車場都有電單車空位或即時狀態。[1]

運輸署官方停車場頁指出其管理的十個政府多層停車場約有 4,000 個私家車位及 650 個電單車位，證明電單車停車與私家車供應不是同一總量；該數字是該頁所述設施範圍，不能外推至所有香港停車場。[3] 運輸署另有「路邊電單車泊位」專頁，指向 HKeMobility 查詢。[2]

本次查閱的公開資料沒有確認：API 的共同 `heightLimits` 對電單車的實際適用方式；`spaceDIS`／`disabilities` 是否能代表電單車可用的無障礙泊位；目前充電資料是否允許電單車進入或充電；以及 HKeMobility 電單車路邊泊位是否提供可供本站整合的即時空位 API。因此以上欄位不應猜測或以通用汽車語義代替。報告只讀程式檔及官方公開來源，未修改任何產品程式或既有文件。
